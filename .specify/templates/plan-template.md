## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Source: `.specify/memory/constitution.md` (v1.0.0). Mark each gate PASS / FAIL /
N/A. Any FAIL must be justified in Complexity Tracking or the plan is blocked.

- [ ] **Spec-first (IV)**: an approved spec exists; unresolved points are recorded
      as pending, not decided here.
- [ ] **Simplicity (II)**: every new layer, pattern or dependency records the
      simpler alternative that was rejected and why.
- [ ] **Separation (III)**: domain logic stays out of UI and controllers; the
      structure / configuration / calculation / published-results split is preserved.
- [ ] **Key-module tests (V)**: changes to classification-code normalization and
      ordering, the distribution algorithm, effective-configuration resolution,
      transactional publication, or public search come with automated tests.
- [ ] **Security by default (VI)**: least privilege, no secrets in the repo,
      server-side validation of every external input, parameterized queries.
- [ ] **Data evolution (VII)**: persistence changes ship as ordered forward
      migrations and update `docs/db.md` in the same change.
- [ ] **Replaceable UI (VIII)**: no business rules in the UI; explicit backend
      contracts; location always presented as approximate.
- [ ] **Observability not blocked (IX)**: errors carry diagnostic context; long
      operations log start/end/outcome; no secrets or private material in logs.
- [ ] **`docs/` is authoritative (X)**: design decisions and domain rules land in
      `docs/`; terminology and the deterministic classification order are preserved.
- [ ] **Private material (Restricciones)**: no BJFF private data
      (`bjff-collection.csv`, `docs/dataset.md`) enters the repo, examples or logs.
